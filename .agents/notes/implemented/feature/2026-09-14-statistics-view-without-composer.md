# Agent Note: 工具统计视图隐藏常驻输入栏并重排「最近调用」行

Status: implemented

## Problem

两个界面问题：

1. **工具统计（`conversation.view` 的 `llm-verifier-statistics`）底部盖着会话输入卡**。统计页是只读看板，
   却和聊天视图一样显示"发消息或创建任务…"输入框，它正好挡住「工具运行明细」表格的下半部分。
2. **「决策快照」面板与「查看详情」的位置不对**。行骨架是
   `gridTemplateColumns: 'minmax(170px,1fr) auto'`，两个入口分别占一行，快照面板还被渲染在
   `<details>` 展开内容**之后**，于是点开的快照看起来属于那个恰好展开的详情块；两个面板也都挤在左侧 1fr 列里。

## Decision

1. **输入栏**：该视图挂载时向宿主的 `conversation.composer` 选择器链注册一个条目
   （`select` 恒返回一个冻结标记、组件渲染 `null`、`priority: 1000` 即最后尝试），选举成立后座位内为空、
   高度塌陷为 0；卸载时 `dispose()` 交还座位。fallback（真正的输入卡）在 overlay 语义下始终保持挂载，
   所以草稿与组件状态原样保留。该句柄只注入 `conversation.view` 的注册，右栏面板与全局看板不注入——
   它们会在用户聊天期间一直挂载。注册失败只 `console.warn`，输入栏保持可见，不拖垮页面。
2. **行布局**：`最近调用` 的每一行改为列结构——首行是身份与耗时/时间（仍用两列网格），
   第二行是并列的两个按钮（`决策快照` / `查看详情`），任何展开的面板都紧贴在按钮下方并占满整行。
   「查看详情」由 `<details>` 改为受控展开（与快照同构，同一时刻只展开一行），两个面板不再互相嵌套。
   文案新增 `recent.detailsHide`（两份字典同步）。

## Alternatives considered

- **注入 `<style>` 隐藏 `[data-composer-seat]`**：能隐藏，但依赖宿主非契约的 DOM 属性，
  且必须靠传入的 prop 区分三种挂载点，否则右栏/全局看板挂载期间会把整个应用的输入栏一起隐藏。
- **让 `select` 读模块级"当前视图"标志**：宿主明确规定链选择器必须是 owner props 的纯函数，
  且切换视图不保证让根组件重渲染，标志可能迟迟不被读到——隐藏会滞后甚至不生效。
- **只让视图 opt-in 宿主的 `data-conversation-composer-overlay` 几何**（轨迹视图的做法）：
  这是宿主原生机制，但输入栏只是改为绝对定位覆盖在内容上，不满足"隐藏"的诉求。
- **保留 `<details>` 只调顺序**：`<details>` 的内容只能紧跟 summary，无法做到"两个按钮一行、快照开在按钮下面"。

## Consequences

- 统计视图不再有输入栏；切回「对话」时输入卡与草稿原样回来。
- 若宿主更换 composer 链的语义或键名，注册会抛错并只留一条告警：退化为"输入栏仍可见"，不会让看板失效。
- 「查看详情」同一时刻只展开一行（此前多个 `<details>` 可同时展开）；快照本来就只展开一行，两者现在一致。
- 客户端无自动化渲染测试，这两项改动靠 `pnpm run build` 后的 Web 看板人工确认；服务端逻辑仍由既有 618 条测试覆盖。
