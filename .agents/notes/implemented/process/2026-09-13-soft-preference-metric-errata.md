# Agent Note: 指标口径勘误（Bradley–Terry 软偏好权重）

Status: implemented

## Problem

best-of-N 的判别力论证建立在一个错误的口径上。该论证把判别探针测得的两个候选对中位分差（0.544 / 0.018）代入
`sigmoid(Δ)` 后得到的 63.3% / 50.4% 称为「单次比较胜率」，并据此得出三处错误结论：

1. 把 50.4% 描述为「接近抛硬币」，即认为难分候选上的选择已经退化为随机；而同一份探针记录里，两组候选在
   10 次重复、A/B 槽位互换下的**方向正确率都是 10/10**。
2. 把样本分差称为「可信区间 / 置信区间」。分差是 Bradley–Terry 软偏好权重映射的输入，与统计置信区间无关。
3. 由此设立「重测 `gap ≥ 0.15` 才可放宽表述」的门槛，并把「判官是否支持 logprobs」当作能否做过程选优的
   前置许可。

这些说法同时写进了 `README.md` 的 best-of-N 使用章节与 `AGENTS.md` 的同名条目，并被后续计划引用；
若不纠正，任何基于「gap」的实验设计都会测错对象。

## Decision

只改说明口径，不动评分、温度、重复轮次与阈值：

- `README.md`：数据表表头由「单次比较胜率」改为「Bradley–Terry 软偏好权重 `sigmoid(Δ)`」，并补一段说明
  （`1 / (1 + exp(-Δ))`、满值 Δ=1 也只有约 73.1%、引擎按确定性累计分排序而非按概率抽签、表内分差不构成置信区间）；
  正文把「抛硬币」改回「区分度不足」，并新增「报告口径」段，明确方向正确率、跨任务选择正确率、平局率、
  重复稳定性、分差与成本是六个不同的量，多裁判 `agreement` 只表示裁判间一致程度（单裁判恒为 1）。
- `AGENTS.md`：把该条目的「可信区间是实测过的，不能省」改写为「判别力的实测结论要按正确口径读」，
  保留原始分差与实测事实，明确**不得再以固定分差阈值或 logprobs 支持与否作为过程选优的准入条件**。
- 既有笔记：在 `.agents/notes/implemented/feature/2026-09-13-best-of-n-generation-side-selection.md` 末尾追加
  `## Errata (2026-09-13)`，逐条列出上述三点勘误并指向本笔记；原正文按历史决策记录保留，不删改。
- 顺带核对该章节里与本轮相关的旧值：流程图中的草稿上限由 `maxTokens 4096/份` 改为 `16384/份`（与
  `caller.ts` 的 `GENERATION_MAX_TOKENS` 一致），成本表 n=4 的「锦标赛」列由 36–54 改为 30–54
  （原值把基线比较的 6 次也算进了锦标赛，`4 + 36 + 6 = 46` 与合计下限 40 自相矛盾；正确的锦标赛上界是
  5–9 场对决 × 3 判据 × 2 轮 = 30–54，加 6 次基线与 4 次生成才等于 40–64）。

## Alternatives considered

1. **直接删掉探针数据。** 不采用。那两组固定候选对的重复测量（60 次真实调用）本身是可复核的事实，
   错的是对 `sigmoid` 输出的解释；删数据等于连证据一起丢掉。
2. **只改 README，不动 AGENTS 与既有笔记。** 不采用。`gap ≥ 0.15` 这条准入门槛正写在 AGENTS 里，
   不纠正它，下一个实现者仍会按旧规约设计实验。
3. **把分差换算成「胜率」并保留该词。** 不采用。PPT 锦标赛用 `sigmoid(Δ)` 作为软权重累加 `wins`，
   不存在「按该概率抽签选取」这一步，叫胜率会持续误导读者。
4. **顺手把 `gap ≥ 0.15` 换成一个新的固定阈值。** 不采用。样本分差不足以支撑任何固定阈值，
   结论应由 P05 的真实任务对照给出。

## Consequences

- 60 次真实探针调用仍然是当前唯一的判别力证据，但它的结论被限定为「这两个固定候选对上方向稳定、
  效果量随难度塌缩」，不再外推成总体可靠性。
- 过程选优（P06）的准入不再取决于通道类型或某个分差阈值，而取决于真实任务对照；这与方案的 M4 退出条件一致。
- 文档与代码复核确认：`src/` 中不存在把分差当作置信区间、断言固定 gap、或按通道限制选优的逻辑，
  本轮没有代码行为变化（除下述 P02 外）。
- 校对时发现的 README 旧值（4096、36–54）一并修正，避免后续引用错值。
