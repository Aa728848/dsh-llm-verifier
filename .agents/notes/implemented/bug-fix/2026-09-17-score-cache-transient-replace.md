# Agent Note: 评分缓存写入改为唯一临时名 + 瞬时替换失败重试

Status: implemented

## Problem

在 Windows 上，`pnpm test` 的全量运行会间歇性失败，两个失败用例都停在同一条语句：

```text
Error: EPERM: operation not permitted, rename
  'C:\Users\...\Temp\dsh-verifier-assembly-xqsFfR\session-1\verifier\scores-v1.json.tmp-3120'
  -> 'C:\Users\...\Temp\dsh-verifier-assembly-xqsFfR\session-1\verifier\scores-v1.json'
 ❯ src/cache.ts:131:13
```

形态是典型的偶发：同一文件单独运行时通过（1.2 秒），全量运行时失败数在两次运行间从 2 变为 1；`src/cache.ts` 的 `persist()` 走的是标准的"写临时文件再原子替换"，本身没有逻辑分支错误。

排查中确认了两层成因，第一层是确定性缺陷：

1. **临时文件名只含 pid，不含写序**。原实现为 `this.file + '.tmp-' + process.pid`，同一进程内两个指向同一个缓存文件的 `ScoreCache` 实例会计算出**完全相同的临时文件名**。两个写者并发时，一方的 `rename` 可能在另一方正持有该文件句柄时发生——Windows 在源文件被打开写入的情况下替换会返回共享冲突，即 `EPERM`。
2. **替换失败没有任何重试**。即便是唯一临时名，Windows 上杀毒软件与索引器也会短暂打开刚写入的新文件，使 `rename` 瞬时失败。这一点在修复过程中被直接观测到：加入重试后，回归测试里同一个写者的 `rename` 调用次数在 1/2/3 之间跳动，说明**该环境下确实存在真实的瞬时失败**，而非仅存在于理论中。

后果不止于测试不稳定：`persist()` 的异常会沿 `getOrCreate` 上抛，导致一次**已经付过费**的判官调用因为缓存落盘失败而整体失败。

## Decision

1. **进程级写序号**：新增模块级 `let replaceOrdinal = 0`，临时文件名改为 `this.file + '.tmp-' + process.pid + '-' + (replaceOrdinal += 1)`。
   注意这里**必须是模块级而非实例级**：第一版写成实例字段 `this.writes`，回归测试立刻抓到两个实例各自从 1 开始、名字依旧相同（断言"两个写者的临时名互不相同"失败）。
2. **新增 `replaceFile(temporary, target)`**：对 `EPERM` / `EACCES` / `EBUSY` 三种瞬时锁码最多重试 5 次，退避 `attempt * 10ms`。重试复用同一个临时文件（无需重写内容）。非瞬时错误码、以及重试耗尽后，**仍然照旧抛错**——不改变原有的失败语义。
3. **保留既有的失败清理**：`persist()` 在 `replaceFile` 抛出后仍执行 `unlink(temporary)`，不留残骸。

## Alternatives considered

1. **把缓存写入失败改为静默降级（不抛错）**：评估后未采纳。这更贴近"缓存只是优化"的直觉，且能顺带消除测试不稳定，但它改变了失败语义：目前落盘失败会让调用方感知到，静默化后缓存与统计的持久化问题将彻底不可观测。本轮目标是消除平台瞬时故障，不是重新定义失败边界；该问题已单独记录，留待需要时决策。
2. **用 `fs.rm` 先删目标再改名**：否决。这会破坏"原子替换"这一根本属性，读者可能观察到不存在的中间态。
3. **改用 `writeFile` 直接写目标文件**：否决。同样牺牲原子性，且并发写会交错出损坏的 JSON。
4. **临时名改用随机数**：可替代方案，未采纳。进程级单调序号足以满足唯一性，且让临时文件名在排查时保持可读、可对应到具体写次。
5. **只在测试里加重试**：否决。缺陷在库代码路径上（两个实例共享一个缓存文件是真实可达的配置），在测试侧掩盖等于把故障留给使用者。

## Consequences

- `pnpm test` 全量恢复稳定：25 个套件、673 passed / 2 skipped，退出码 0；此前失败的两个用例不再复现。
- 缓存写入对 Windows 上杀毒/索引器造成的瞬时锁具备容忍度，一次已付费的判官调用不再因为落盘抖动而整体失败。
- 新增 3 条回归测试，覆盖三类边界：注入 2 次瞬时失败后快照仍落盘（且断言**重试复用同一个临时文件**）、注入无限失败后**仍在 5 次尝试后抛错**（保证没有把失败悄悄吞掉）、两个写者共享一个缓存文件时**临时名互不相同**（该断言在旧实现下必然失败）。
- 测试实现方式：把故障注入到被 `vi.mock` 替换的 `rename` 上，而不是在断言里放宽期望值——这一点很关键，第一版断言写成了精确的调用次数，随后被"真实瞬时失败也会触发重试"这一事实证伪；最终断言改为不变量（"不同写者的名字集合大小等于写者数"、"重试耗尽后仍抛错"），既稳定又确实能在旧实现上失败。
