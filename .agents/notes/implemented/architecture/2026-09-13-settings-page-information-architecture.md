# Agent Note: 设置页信息架构重做（声明式字段注册表）

Status: implemented

## Problem

设置页是一个 5000px 高的单列表单：41 行手写的 `<div style={row}>`，其中「自动验收」一段就占 26 行，每行都是 `<Label/>` + `numeric()` 的逐字复制。这带来四个具体问题。

1. **信息架构失衡**：策略开关（调用策略、判据、阈值）与纯内部量（证据字符预算、调用预算、路由次数上限、缓存条目、单价）混在同一段里，顺序也是交错的；用户打开页面先看到 26 行「自动验收」，其中大部分不该由人来调。
2. **高度由说明文字驱动**：52 条 help 平均 85 字符、最长 858 字符（`field.autoProcessSelection.help`），在 288px 宽的控件列旁边折成 3–5 行 12px 小字，整页因此超过 5000px；保存/重新加载按钮位于页面**最后一行**，改一个开关要滚到底。
3. **没有导航**：没有折叠、没有搜索、没有目录；找一项设置只能滚动。
4. **校验只在保存后出现一次**：`numeric()` 只挡 `min`，所以 `temperature` 能填 5、`autoVerifyThreshold` 能填 1.5、`autoRouteMaxInputChars >= autoRouteMaxItemChars × 2`（`config.ts:273`）完全不检查。真正的报错来自宿主的 `validate: resolveConfig`，渲染成页面底部的一行字符串，不指向任何字段。

同时 `values()` 里的默认值是**内联**的：表单既不显示哪些项被改过，也没有「恢复默认」。

## Decision

把设置页从「手写 JSX 列表」改成「**声明式字段注册表 + 通用渲染器**」，并在这张表上重建导航与校验。

新增 `src/client-fields.ts`（纯函数，由 `client-fields.test.ts` 直接测试）作为唯一事实来源：

- `CONFIG_DEFAULTS`：插件默认值。`valuesFromView()` 从它派生（`client.tsx` 的 `values()` 只是它的一层包装），行内「恢复默认」（`resetField`）与 `balanced` 预设写同一个对象，因此「空表单显示的值」与「恢复默认写回的值」不可能分叉。
- `FIELDS` / `SECTIONS`：41 个字段的元数据（分区、控件种类、数值边界、整数性、滑块、单位、可见条件、是否可重置）与 8 个分区（`tier: core | advanced`、默认展开状态）。渲染器、折叠、可见性与校验全部由它驱动。
- `validateValues()` / `textIssue()`：前端校验**只镜像** `resolveConfig` 里真实存在的规则（范围、正整数、整数、缓存目录相对性、`autoRouteMaxInputChars ≥ autoRouteMaxItemChars × 2`、provider/model 非空），返回 `{key, code, params}` 而不是成句文案，由页面用 `settings.invalid.<code>` 本地化。**判据文件在 `custom` 下允许为空**（解析器退回 `coding` 并告警是有意设计），因此不在前端校验里。
- `PROFILES` / `applyProfile()`：四套快速配置（默认平衡 / 严格验收 / 省额度 / 仅工具）。只拥有**策略类**字段；裁判模型、判据、存储、执行与单价不在其中。预算写成 `recommendedBudgets(裁判数, 判据数)` 的安全下限（复用 `computeWorstCaseBudget`），因此任何一套预设都不会触发预算告警。
- `activeProfile()`：下拉显示的当前预设由它判定（逐项比对该预设拥有的策略字段），任何手改都显示为「自定义」。**派生预算不参与判定**：预算只是当前裁判数下的安全上限，手调预算不该让一个没有改动策略的配置变成「自定义」。
- `renderSections()` / `sectionSummary()`：按当前取值过滤出真正要渲染的字段（`criteriaFile` 只在 `custom` 下出现），折叠分区用当前取值做摘要。

`src/client.tsx` 的渲染相应重写：

- 8 个可折叠分区，core 区默认展开（工具 / 自动验收 / 裁判模型），其余默认收起并在标题栏显示「高级」标记 + 取值摘要。默认展开 17 行 → 约 1200px（原 41 行 / 约 5000px），另加「展开全部 / 收起全部」。
- 行布局从两列 grid 改为 `flex-wrap`（标签最小 220px / 控件最小 170px）：窄面板下控件换行到标签下方，不再把 help 挤成 5 行。
- 每行显示「已改」徽标与「恢复默认」（身份类字段不可重置）；数字项显示单位，0–1 字段附滑块。
- 顶部摘要条：当前模式 · 判据 · 阈值 · 裁判数 · 最坏调用量（复用 `evaluateBudgetWarning`）。
- 行内校验：输入期间用 `textIssue` 即时反馈（越界 / 非整数 / 空），提交后用 `validateValues` 报跨字段问题；有问题的字段就地标红，保存按钮禁用，页脚显示「有 N 项需要修正」+「跳到第一处问题」（跳转前展开所属分区、scrollIntoView 后聚焦）。
- 保存/重新加载移入 `position: sticky; bottom: 0` 的页脚，未保存/已保存/错误状态常驻可见。
- 「快速配置」下拉是一个**有状态**的选择器：显示当前生效的预设（`activeProfile`），选中即写入该预设，「默认平衡」把策略类字段恢复为插件默认值；另有「按当前裁判数填入推荐值」按钮（只写两个预算字段）。

新增 i18n 键 42 对（zh/en 各一份）全部进入 `client-i18n.ts`；新模块加入 `AGENTS.md` 的结构表，硬性规矩 10 的「UI 行」改为「在 `FIELDS` 里加一行」。

## Alternatives considered

- **只做折叠，不改数据模型**：把 41 行原样塞进 `<details>` 能立刻变短，但逐行校验、默认值徽标与值相关的可见性都需要「字段元数据」，最后仍要写出这张表；先折叠等于把同一件事做两遍，而且复制粘贴出来的 26 行仍留在文件里。
- **搜索框（已实现后又移除）**：第一版按标题、help 原文与配置键过滤，并对命中分区强制展开。实机评估后按用户要求移除：41 个字段配上分区折叠与摘要已经够用，搜索框与「命中即展开」只是多出来的一层交互；`renderSections()` 保留下来，将来若要恢复搜索只需在它之上再过滤一次。
- **「快速配置」做成动作菜单（已实现后又移除）**：第一版把下拉做成 `value=""` 的动作菜单，选中即套用并立刻回到占位文案。实机反馈是「每次打开都显示快速配置」——用户无法看出当前生效的是哪一套，也无法确认能否切换或回到默认。改为有状态选择器（`activeProfile()` 决定显示值，套用后停留在该预设上），「默认平衡」即回到插件默认值。
- **把 UI 偏好（分区展开状态）写进配置 schema**：那会新增配置项，按硬性规矩 10 必须同时改 schema、`resolveConfig`、两份文案与 README，并让「UI 折叠状态」成为宿主持久化契约的一部分。折叠状态改为组件内状态，不做持久化。
- **沿用 `loaded.settings.base` 作为「默认值」**：`base` 是宿主 installSection 的组成基准（本部署的插件配置），把它当默认会让「恢复默认」在不同部署下写回不同的值。改用插件自身的 `CONFIG_DEFAULTS`，语义与 README 的默认值一致。
- **继续给 `numeric()` 逐项传 `min` 参数**：最小侵入，但 `max`、整数性与跨字段关系无处安放，且每加一个字段都要记得传参。改为在注册表里声明、由 `validateValues` 统一推导。
- **按模式隐藏 `manual` 下无用的字段**：会让「先配好再切模式」不可用，也掩盖了字段确实存在的事实。改为折叠 + 摘要，全部保留可达。
- **把长 help 藏进 hover 提示**：长 help 是高度的一半来源，但把说明藏起来会让本就不易发现的开关更难发现；改用「高级分区默认收起」承担这件事，说明文字保持常显。

## Consequences

- 设置页默认高度从约 5000px 降到约 1200px；分区摘要让收起的高级分区仍然可读。
- 新增配置项的改动面从「手写 JSX + 两份文案 + README」变成「`FIELDS` 加一行 + 必要时给默认值 + 两份文案 + README」，校验规则写在字段声明上而不是散落在 JSX 里。
- 前端校验与宿主校验是**两份实现**，这是本次唯一的真实风险。缓解方式：只镜像 `resolveConfig` 中确实存在的规则，并在 `client-fields.test.ts` 里逐条锁定（越界、整数、缓存目录、两项预算关系、`NaN`、判据文件允许为空）。多镜像一条就会挡住宿主接受的保存，因此新增规则前必须先确认 `config.ts` 真的会拒绝它——这条已写进 `AGENTS.md` 的「已知的有意设计」。
- 折叠状态是本地 UI 状态，不落配置；重载后回到默认展开集合（core 展开、高级收起）。预设选择器不拥有独立状态：它显示的是当前取值是否恰好等于某套预设，而没有等于任何一套时显示「自定义」。
- 已验证基线：`pnpm run typecheck` 通过；`pnpm run build` 通过且 `lib/` 已重建；注册表与校验的全部断言通过——本会话内用等价的 Node 断言脚本跑出 `ALL CHECKS PASSED`，同一组断言已写入 `src/client-fields.test.ts`。**受限沙箱下 vitest 因 esbuild 的 piped stdio `spawn EPERM` 无法启动**（`AGENTS.md` 已记录该边界，本会话尝试放宽权限未获放行），因此 `pnpm test` 未能在本会话内真实执行，新增测试文件尚未经过 vitest 运行，需要在无沙箱环境补跑 `pnpm run verify:release`。
- 未验证项：React 组件的实际渲染（折叠、滑块、粘性页脚、跳转聚焦）没有自动化覆盖。本仓库的测试约定是只测纯函数、不写 DOM 集成测试，因此这部分依赖类型检查与代码审阅。
