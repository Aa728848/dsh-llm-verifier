# D1 二十档标尺与自动概率评分

## 背景

二元 pass/fail 太粗:一次交付的失败有程度差异,而门控需要一个可比较的连续量。同时,模型的自我陈述不可作为完成证据。

## 决定

- 判官在 A–T 二十档上给出判定,等距映射到 `[0,1]`:字母序号 ÷ 19。
- 进度追踪复用同一把尺子但方向相反:A 是"确定尚未完成"。
- 分数优先取判官回答处 `top_logprobs` 的 A–T 候选分布,重新归一化后算加权期望。
- 同一字母的多个 token 表面形式(如 `"A"` 与 `" A"`)是互斥采样结果,概率**相加**。
- 通道能力在运行时探测,失败降级到显式字母标签,并写入按话题持久化的能力记忆(24 小时 TTL)。
- `finish_reason: 'length'`(推理吃满输出预算)抛独立错误,不写能力记忆。

## 后果

- 求和与上游取最大值的结果不同,足以跨过通过阈值。一致性测试的 fixture 有意不覆盖该情形,否则必然失败。
- 显式标签通道每次只采一个字母,单档步长 5.3%,所以进度追踪默认重复 3 轮取平均。
- 一次"预算配小了"的调用不会污染能力记忆,该路由不会因此被判成"不支持 logprobs"。

## 未采纳的第三条通道

上游还有第三条评分通道:当地提供的模型服务不输出分数标签时,由上层**预填**标签并把下一个 token 约束到这二十个字母上,再读它的分布。这样任何 OpenAI 兼容服务都能当分布打分器,信息量严格多于本仓库显式标签通道的单次采样——上游能在 K=1 跑就是因为这个。

本仓库没有实现,原因是直接传输层说的是 provider 声明的普通 OpenAI 兼容端点,而预填/文法约束是 vLLM / SGLang 的扩展参数,普通端点会拒绝。要加它得先满足两条前提:(1) 宿主流适配器暴露预填或受约束解码选项,或该路由已知是本地推理服务;(2) 能力探测能在运行时判定支持并降级到显式标签——**绝不**按 provider 或模型名判断。落地位置是 `callTopLogprobs` 的一个可选第三模式,届时进度追踪的重复轮次可以下调。
