# D9 请求级过程选优在 llm/stream 上投机并发

## 背景

插件其余能力都发生在已产生回复之后。要在回复交给宿主**之前**改变下一步动作,只能拦在主模型的流式输出上。

## 决定

挂宿主的 `llm/stream` waterfall,默认关闭,三档:

| 档 | 触发 |
| --- | --- |
| `off` | 完全不进入该路径 |
| `recovery` | 同一任务最近两次已完成的验证运行**都失败** |
| `every-step` | 每个主循环请求,每任务上限 `maxProcessCyclesPerTask` |

机制:意图在请求派发**之前**登记 → 下游派发一次并缓冲原回复(上限 1 MiB)→ 生成 N-1 份备选 → 按 process 判据比较 → **只回放胜者**。

- 生成与原回复**并发**,比较仍串行。
- 胜者按原始 chunk 原样回放,工具调用的 id、名称、参数都不改写。
- 候选动作以块为原子单位:动作块放不进分摊预算时,整周期回退原回复并记 `view-over-budget`。

## 后果

- 主回复被整条缓冲,聊天界面在周期跑完前没有流式文字。
- 投机并发要付一次可能作废的生成:原回复超限、finish 不合法、内容为空或周期中途失效时,仍如实记成 `purchased: true` + `generatedCalls: 1`。
- 选优**不是**验收:胜者交给宿主后,最终验收照常覆盖随后产生的实际工作。
- 缓存命中率、延迟与替换收益必须由真实任务对照评估,不能由钩子存在推导出来。

## 为什么指示器只能是内存态

宿主的行内提示("正在压缩上下文…")由一对**会话事件**驱动,而这条路对仓库外插件是关闭的:持久化读路径会拒绝解释含 `KNOWN_SESSION_EVENT_TYPES` 之外事件类型的日志,除非记录带 `ignorable: true`,而 `Session.append()` 无法写入这个标记——只有 seed/restore 的信封能带。写一条自己的事件类型会让整个话题无法加载。

所以本插件**一条会话事件都不写**:路由器的预约状态机与 P06 选择器把进度写进内存表,插件既有的 RPC 增加一个只读查询,客户端只在回合运行中、或刚结束的 20 秒内轮询它。重载后什么都不显示——那个周期确实已经不存在。长期记录仍然只有统计看板。
