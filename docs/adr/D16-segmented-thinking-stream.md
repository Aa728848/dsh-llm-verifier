# D16 辅助思考按高浪费片段提前压缩并流式提交

## 背景

D15 的整块实现要等到思考块结束才发起辅助调用，超过 24,000 字符的块还会直接跳过。它既拉长了静默窗口，也无法处理最典型的失控长思考。与此同时，主 Agent 可能必须始终使用用户选择的最高思考深度，辅助模块不能通过改变主请求 `reasoningEffort` 来减少生成本身。

整块重写还从第一个字符开始改变历史文本。DeepSeek 的缓存按完整前缀单元匹配，流式分块本身不会改变缓存结果；真正重要的是最终写入了什么，以及第一次修改出现在哪里。

## 决定

- 主请求对象保持只读，尤其是用户选择的 `reasoningEffort`。辅助线路自己的强度解析仍按 D15，不回写主请求。
- 思考按原文偏移分段，普通段最多 2,000 字符；达到 400 字符后可优先在空段边界切分。检测只规范化比较副本，实际回放不做空白或 Unicode 规范化。
- 只用确定性的重复句与重复 shingle 比例识别高浪费片段，阈值 0.5。长度达到 400 只是必要条件，不再足以触发辅助调用；检测不确定时保留原文。
- 普通片段一旦成段就按原文流式提交。每个思考块至多一个候选区间、一次辅助调用，每个会话至多一个进行中的辅助调用。
- 候选区间关闭后立即提前调用，不等待块结束。辅助增量通过 `BlockAssembler` 私有流式组装，不进入主流；只有完整、自然结束且通过现有校验的替换文本才能提交。
- 候选后的原文进入有界有序队列，上限 24,000 字符。候选 ready 后可在块结束前提交并释放队列；超时、失败、队列超限、源流异常或提前终止则中止调用并回放候选原文。
- fail-open 以未提交候选为边界。已经按段交给宿主的原文或替换文本不能撤回。块结束文本由实际发出的片段顺序组装，其他 chunk 字段和 replay metadata 保持原状。
- 不改写历史块，不因设置或算法变化重算旧摘要。指标增加提前调用、分段数量、最大缓冲和保留前缀字符数，仍是进程内内存态。

## 后果

- 这是段级流式，不是辅助模型每产出一个 token 就立即替换主流。普通短段若没有段落边界，仍可能等到 2,000 字符或块结束才提交。
- 提前调用让压缩与主模型后续生成重叠；段级提交缩短整块静默，但不能承诺零缓冲或零延迟。
- 最小差量只能保留第一次修改位置之前可能匹配的缓存前缀，不能保留原始模型输出末尾的完整缓存单元，也不能承诺缓存收益。
- 本地检测器只识别高重复浪费，不声称理解所有语义上的无效思考。每块一次调用的上限意味着后续异常片段会保留原文。
- 已提交后的源流失败只能回放剩余原文，不能恢复整块原文；这是提前流式提交相对 D15 整块方案的明确取舍。
- 改写文本与既有签名的组合仍未做真实端点验证。本轮只运行离线 scripted streams 与自动化测试，真实 V4.1 Flash 的行为和净收益留待后续单独验收。
