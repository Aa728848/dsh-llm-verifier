# D10 证据的单/双层层限长与分摊

## 背景

会话轨迹、候选、检查点、文件改动都可能很长。判官请求一旦顶爆上下文,这次调用就废了;而"整条决策被上限丢弃"的成本更高。

## 决定

- **双层**:单项上限(默认 20000 字符)与整次输入上限(默认 60000 字符)。
- **分摊**:多个来源共享总预算时按数量用 `itemBudget()` 分摊,不允许裸值直接截断。
- **计量按实际渲染文本**:分隔标记、ID、截断提示本身都计入预算。
- **语义路由的占位符上界**:用 13 字符的内容派生 token 占位符测量每个块的实际渲染长度;占位符长度是真实渲染长度的上界,因此一遍筛选不会越过预算,同时保留最新证据。
- **显式工具证据**另有总量上限:`自动路由证据总上限 × 2`,且绝不突破 24 万字符。
- 超出时整条决策丢弃,并在统计里记 `dropped-over-budget`——零模型调用,但读者能回答"这次为什么没路由"。

## 后果

- 截断后的条目不会被判定为超限,因此边界值可测。
- 自动 `track` 最多渲染最近 6 个检查点,被略过的数量写在首个检查点里。
- 主 Agent 的必要约束放不下时**回退**而不是裁剪:拿被裁剪的约束去判候选,判的是裁剪本身。
