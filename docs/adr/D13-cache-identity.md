# D13 缓存身份与四层定价

## 背景

一次验收会发出几十次判官调用。缓存命中能省下真实费用,但命中脏缓存会把错误结论带进门控。同时宿主不向插件暴露任何价格。

## 决定

**缓存键**包含:完整渲染后的提示词、评分通道、provider、model、推理强度、输出上限、轮次编号、图片摘要。

- 按调用前**预测**的通道查询,但始终按响应**实际**的通道写入。
- 相同并发请求合并在途 Promise。
- 失败或被取消的请求不写缓存。
- 提示词文本变化自然失效;provider/model/effort/maxTokens/repeat 这类身份字段改动必须手动升 `cache.ts` 的 `version`。

**定价四层**,按顺序取第一个命中:

1. 手填单价(填了任意一个,整组以手填为准);
2. 本机 pi-ai 模型目录(离线);
3. models.dev 快照(在线兜底,进程内缓存 24 小时);
4. 未定价,记 0。

匹配只认**精确的 provider + model**。

## 后果

- 同一个 model id 在 models.dev 上有二十多家 provider 挂牌、价差数倍,跨厂商取价等于往成本列写一个编造的数字。转售路由要用 `priceProviderOverride` 明确指定跟随谁。
- 缓存读取 token 走专用单价,留 0 时退回按输入价计算。
