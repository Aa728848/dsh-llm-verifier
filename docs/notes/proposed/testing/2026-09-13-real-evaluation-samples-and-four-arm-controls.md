# Agent Note: 真实评测样本与四组对照（P05 / S05-B 计划）

Status: proposed

## Problem

P01–P03、P06 的工程批次改变了插件在真实任务上的行为，但这些改变收益如何、该保留还是回退，没有任何数据支持：

- 「过程选优」在关闭时与旧路径一致是**代码事实**，开启后是否值得，只能由真实任务对照回答；
- 阶段判据（proposal/artifact）是否让早评审更早影响实施，需要看「评审完成早于首次采用候选的操作」，而不是看 steering 是否发出；
- 离线回放（`replay.ts` + `scripts/eval-replay.mjs`）只能重放**历史记录**与**调度规则**，它**不能**证明共享一份上下文是否会改变后续实施——那必须重新跑任务。

本项是计划里的 P05/M4，也是既有 S05-B 的直接延续。**本轮不交付它**：真实模型对比需要预先选定的数据与明确的调用/token 预算，而制定方案本身不等于已授权无限量模型实验。因此本笔记只登记**可执行的设计**与**尚未交付的事实**，不宣称任何评测已完成。

## Decision

### 已存在的基建（本轮之前就已入库，本轮未改）

- 样本 schema（`replay.ts` 的 `EvaluationSample` / `parseEvaluationSample`）与 `samples/strategy/README.md`：`{ id, category, shouldReview, expectedPhases, events }`，`category` 固定为 `code` / `research` / `writing` / `candidates` / `long-task` / `conversational`。
- 离线回放：`pnpm run build` 后执行 `node scripts/eval-replay.mjs --samples samples/strategy`，报告触发 precision/recall 与各阶段覆盖（纯确定性层，无模型调用）。
- 阈值扫描（`sweepThresholds`）、解析器 drift 回放（`replayDecisionScores`）与路由周期汇总（`summarizeRouteCycles`）。

### 尚未交付（本笔记的执行设计）

**数据**：首批约 30 条脱敏真实任务，覆盖代码 / 研究 / 写作 / 同题候选与不同子任务 / 长任务 / 纯对话；预先标注「应否评审、候选分组、评审阶段、合适介入点、最终要求是否满足」，标注依据是**产物与真实证据**，不得用裁判分数反向标注。固定候选对的重复次数与独立任务数量**分别报告**。

**四组对照**（模型、通道、判据、预算分别固定；变更阶段判据的实验单列）：

| 组 | 配置 | 隔离的增量 |
| --- | --- | --- |
| A | manual | 基线：完全不自动评审 |
| B | 冻结的当前 smart | 现状 |
| C | 阶段/早评审改进 + 过程开关关闭 | P01–P03 的增量 |
| D | 同一改进版本 + 过程开关开启 | P06 的增量 |

先在约 6 条**确有恢复需求**的任务上做小规模配对运行，再扩到约 30 条分层样本；样本预先选定，失败案例保留。阈值与解析回放只能验证历史与调度，**早反馈是否改变后续实施必须重新运行任务来确认**。

**指标**：路由 precision/recall、阶段选择正确性、候选选择正确率与平局率、重复测量稳定性、最终误放行 / 误阻断 / 未验收退出、首次正确方案出现时间、返工与主 Agent 续步数、总模型请求与已知 token、P50/P95 延迟。P06 单列：触发率、跳过原因分布、备选胜出率、**有效替换率**、重复/相同候选率、回退率、从请求开始到首个可见输出的延迟。备选胜出**不等于**最终质量提升；失败缺失用量、explicit-tag / top-logprobs / 裁判降级分组报告。

**准入与判据**：试验前登记可接受的额外 token/延迟与回归判据；收益不足则过程选优**继续默认关闭**，不得用备选胜出率替代收益结论。30 个样本不足以支撑低错误率结论，报告必须保留样本量与不确定性。证据不足时不调整 `autoVerifyThreshold`、`autoTrackCompletionThreshold`、`autoRouteMinConfidence` 与各重复轮次（现状即如此，本轮未动这些值）。

**研究与写作覆盖**：先确认「不产生写入但交付重要研究结论」这类漏检样本，再为可识别的任务/交付信号增加窄触发规则；不因为切换了 `research` / `writing` 预设就把所有聊天强制验收，也不把写文件当成重要性的替代指标。

## Alternatives considered

1. **用离线回放代替真实对照。** 不采用。回放读的是历史记录，无法证明「同一任务在另一套策略下会走向不同实施」；计划对此有明确结论。
2. **把方案文档本身当作 P05 的交付。** 不采用。计划明说不把样本说明文件算成交付，本笔记因此标为 `proposed` 并逐项列出**未**交付的内容。
3. **先跑一次大规模真实实验再写设计。** 不采用。没有预先登记的数据范围与预算，实验开销无法控制，也无法在事后区分效果来自 P03 还是 P06。
4. **只测过程选优（组 D vs C）。** 不采用。没有 A/B 基线，「过程选优是否有用」与「整套改进是否有用」会纠缠在一起。
5. **用裁判分数当标注依据。** 不采用。那等于用被测对象标注被测对象。
6. **本轮以「收益未知」为由回滚 P06。** 不采用。P06 默认关闭，回滚并不能回答任何问题；保留代码并保证关闭态逐位不变，是等待数据的正确状态。

## Consequences

- 现状（P06 默认关闭、阈值未动）给出一个可安全等待数据的状态；本笔记只把实验设计固定下来，**没有**产生任何可引用的结论。
- P04 的「定位诊断 + track 观察式调度」已于同日实现（见 `implemented/feature/2026-09-13-located-findings-and-observation-only-track.md`）：诊断部分不受实验结论约束，而**观察式调度是实验性的**——arm B（现状 smart）与 arm C/D（含新调度）的对照正是决定它去留的依据；若收益不足，回退方式是把该分支恢复为无条件 steering。
- 下一次执行 P05 时必须先选定：数据来源与脱敏方式、模型与通道、每条任务的调用/token 上限、运行次数与超时；然后按上表分组跑，并把报告与失败案例一起提交。
- 已知风险：样本量小、判官在难分候选上的区分度有限（见 P01 勘误），因此「某组更好」这类结论必须连同不确定性与失败案例一并报告；若收益不足，回退手段是 P06 保持关闭，必要时恢复 P04 之前的调度。
- 与其它批次的关系：P01 已纠正指标口径（不得再用固定分差阈值或 logprobs 支持作为准入条件）；P02/P03 的阶段语义与 P03 的 `context` 都是本项要测的变量之一。
