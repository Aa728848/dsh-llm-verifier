# Agent Note: 补上宿主面接缝测试（配置 schema 往返 + 判官自检路由）

Status: implemented

## Problem

单元测试只证明模块正确，不证明**宿主看到的接口**正确。本轮新增了配置项与一条 RPC 诊断路由，两者都跨过宿主边界：
配置由宿主的 schema 校验已存值，探针由宿主带着（或没有）agent 调用。

前一批缺陷正好证明了这类问题的代价：`summarizeVerdict` 的字段形状不匹配让 11/11 条会话验收记录静默丢数据，
而测试一直绿着——因为它喂的不是被测路径**真实产出**的形状。

## Decision

1. 装配级测试 `src/config.test.ts`：`Config → JSON → Config → resolveConfig` 往返，覆盖全部预设值、trim 行为与默认值
   （宿主就是用这个 schema 校验已存配置的）。
2. 装配级测试 `src/index.test.ts`：经插件装配驱动判官自检路由——无 agent 时必须说明原因、默认用 coding 判据、
   自定义文件不可用时**带原因**退回 coding、真实文件能解析、判官失败必须**被报告**而不是崩溃或静默成功。
3. 交付前自查把两处形状不匹配的缺陷提升为回归测试：会话验收的逐项判据形状（`d37c6ee`）与回放标签选择（`3dc50c6`）。

## Alternatives considered

1. **只靠 `pnpm run typecheck`**：否决。两条依赖线（npm 锁定版与本地 checkout）结论可能不同，且类型正确不代表宿主看到的形状正确。
2. **只测纯函数、不测装配**：否决。这正是缺陷藏身之处——装配层传的形状与纯函数的假设不一致。
3. **给每个工具都写端到端集成测试**：否决。成本过高；本项目约定是「每个模块一份同目录测试 + 少量装配级契约测试」。
4. **让测试喂「看起来对」的假数据**：否决。教训已经明确——必须喂被测路径真实产出的形状。

## Consequences

- 配置与自检两条宿主边界有回归保护；schema 往返能提前发现「宿主校验通过但 `resolveConfig` 拒绝」这类不一致。
- 约定固化在 `AGENTS.md` 的测试节：不写跨模块的大集成测试，但装配级契约要有，且测试数据必须来自真实产出形状。
