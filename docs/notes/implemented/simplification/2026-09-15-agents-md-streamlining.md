# Agent Note: 精简与分层治理 AGENTS.md 规则文件

Status: implemented

## Problem

仓库面向开发代理的指导文件 `AGENTS.md` 经历了多轮迭代和故障防御累积，体积增长至 58.7 KB（折合 1.6 万 ~ 2 万 Tokens）。在 Antigravity / DSH 开发环境中，该文件会在每次会话中被完整注入，导致：
1. **首轮对话上下文开销过大**：即便处理小型重构或简单修复，也要预先消耗巨额 Token。
2. **注意力稀释（Attention Dilution）**：关键的发版与构建红线被淹没在长篇大论的实现细节、排错历史流水账和数学推导中。
3. **职责混杂**：特定模块（如 P06 过程选优、Best-of-N 理论胜率测算、Windows NTFS 硬链接解绑）的深层设计，全部平铺堆叠在“已知的有意设计”单个小节中，阅读和维护难度高。

## Decision

对 `AGENTS.md` 进行结构化分层重构与提炼瘦身，在 100% 完整保留既定工程约束与红线的前提下，将体积压缩约 74%：
1. **结构化归类**：将原先无序杂乱堆叠的 40+ 条“已知的有意设计”，按业务领域归为 6 大清晰板块：
   - 验收与门控核心
   - 路由与调度策略
   - 评分引擎与判官通道
   - 过程选优（P06）
   - 生成侧工具（Best-of-N）
   - 观测、脱敏、账目与设置
2. **剔除辩护性冗余叙述**：将每条设计提炼为“核心事实 + 禁止操作 + 核心原因”，删除代码变量排错流水账与重复推导，历史事故溯源与实验数据沉淀至既有的 `.agents/notes/`。
3. **硬性规矩精练化**：保留 13 条黄金守则的核心红线，去除冗余的底层原理长文。

## Alternatives considered

- **直接拆分成多个独立规则文件并全部删除顶层总表**：可能导致部分全局 Agent 遗漏某些模块的跨边界约定；保留顶层清晰的结构化摘要是最佳平衡。
- **大幅删减有意设计条目**：高风险。历史证明这些“有意设计”一旦在规则中缺失，极易被后续 Agent 当作 bug 误修，因此必须 100% 完整保留其核心结论。

## Consequences

- `AGENTS.md` 体积由 58.7 KB 降至 15.3 KB（减少 74%），显著降低每次会话的冷启动延迟与 Token 开销。
- 6 大领域分类使规则边界更加清晰，Agent 对核心发版红线与意图设计的遵循度明显提高。
- 完整通过 `pnpm run verify:release` 发版门禁。
